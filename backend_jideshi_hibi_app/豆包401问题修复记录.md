# 豆包 API 401 问题修复记录

## 问题现象

- 前端发消息后提示：**请求失败: 500 - 模型 API 错误 401**
- 错误详情中出现：`invalid_api_key`、链接 **https://help.aliyun.com/zh/model-studio/error-code#apikey-error**

说明请求被发到了**阿里云模型服务**，而不是火山方舟豆包；豆包的 API Key 在阿里云上会报 401。

---

## 根本原因

后端实际请求的 `MODEL_BASE_URL` 是**阿里云 DashScope**（如 `https://dashscope.aliyuncs.com/compatible-mode/v1`），常见情况包括：

1. 曾按「阿里云 / 通义」部署文档配置，`MODEL_BASE_URL` 写的是 dashscope 地址；
2. 用 `docker run -e MODEL_BASE_URL=...` 把阿里云地址写死在命令里，之后只改 `.env` 再 `docker restart`，**环境变量不会变**（容器仍用启动时的 `-e` 值）；
3. 服务器上的 `.env` 已改为豆包，但容器未用 `--env-file .env` 重新创建，仍在使用旧环境。

---

## 修复方法

### 一、确认服务器上的 .env 为豆包配置

在服务器上编辑 `~/jideshi_hibi_backend/.env`（或实际部署目录），保证内容为：

```env
MODEL_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
MODEL_API_KEY=你的豆包API密钥
MODEL_ID=你的推理接入点ID或模型ID
PORT=7861
```

注意：

- `MODEL_BASE_URL` 必须是 `https://ark.cn-beijing.volces.com/api/v3`，不能含 `dashscope`、`aliyuncs`；
- `MODEL_API_KEY` 从火山方舟控制台复制**完整** API Key；
- `MODEL_ID` 可为模型 ID（如 `doubao-seed-2-0-pro-260215`）或推理接入点 ID（`ep-xxxxx`），以控制台为准。

### 二、用 .env 重新创建容器（关键）

仅改 `.env` 再执行 `docker restart` **不够**，必须删掉旧容器后用 `--env-file .env` 重新创建，新环境变量才会生效。

在服务器上执行：

```bash
cd ~/jideshi_hibi_backend
docker stop jideshi_hibi_api
docker rm jideshi_hibi_api
docker build -t jideshi_hibi_api .
docker run -d \
  --name jideshi_hibi_api \
  --restart unless-stopped \
  -p 7861:7861 \
  --env-file .env \
  jideshi_hibi_api
```

或使用项目内的一键脚本（需先同步 `server_redeploy.sh` 到服务器）：

```bash
cd ~/jideshi_hibi_backend
chmod +x server_redeploy.sh
./server_redeploy.sh
```

### 三、验证是否生效

```bash
docker exec jideshi_hibi_api env | grep MODEL_
```

应看到：

- `MODEL_BASE_URL=https://ark.cn-beijing.volces.com/api/v3`
- `MODEL_API_KEY=...`（完整密钥）
- `MODEL_ID=...`（与 .env 一致）

若仍为 `dashscope.aliyuncs.com` 或 `qwen-plus`，说明容器未用当前 `.env` 启动，需按「二」重新创建容器。

---

## 如何判断是阿里云还是豆包返回的 401

- 错误信息里出现 **help.aliyun.com** → 请求打到了**阿里云**，需检查并改为火山方舟的 `MODEL_BASE_URL`，并用 `--env-file .env` 重建容器。
- 错误信息为 **"The API key format is incorrect"**、**"AuthenticationError"**、**"Unauthorized"** 且无 aliyun 链接 → 请求已到**火山方舟**，多为：
  - `MODEL_API_KEY` 未填、填错或复制不完整（从火山方舟控制台重新复制完整 Key）；
  - 或 `.env` 修改后未重启服务（systemd：`systemctl restart jideshi-hibi-api`；Docker：需用 `--env-file .env` 重建容器）。
- 若仍 401，可检查 MODEL_ID 是否需改为推理接入点 ID（如 `ep-xxxxx`），参考 `豆包Pro配置说明.md`。
