# 智能体对话原理说明

本文档说明「助理」中智能体对话的完整数据流：前端如何组包、后端如何拼接与加工、大模型 API 如何调用、以及回复如何回传与展示。

---

## 一、整体流程概览

```
用户输入 → 前端组包(消息+历史+智能体信息) → HTTP POST /api/chat
    → 后端解析 + 拼 system prompt + 规范化 history
    → 组装 messages → 调用大模型 /chat/completions
    → 取完整 reply → 返回 JSON
    → 前端解析 reply → 写入本地并展示
```

---

## 二、前端：发送前如何拼接与组包

### 2.1 数据来源（`agent_chat_page.dart`）

| 字段 | 来源 | 说明 |
|------|------|------|
| 当前用户消息 | `_inputController.text.trim()` | 用户本次输入，发送前会先写入本地消息列表并清空输入框 |
| 历史消息 | `widget.repository.getMessages(widget.agent.id)`，并**排除本条刚加入的 user 消息** | 每条为 `{ role: 'user'\|'assistant', content: string }` |
| 智能体名称 | `widget.agent.name` | 创建/编辑智能体时设定的名称 |
| 智能体职能 | `widget.agent.role` | 创建/编辑智能体时设定的职能描述 |
| 智能体 ID | `widget.agent.id` | 本地唯一 id，用于区分不同智能体与对话记录 |

前端**不会**在本地拼 system prompt，只负责把「当前轮用户消息 + 历史多轮 + 智能体名称/职能」原样传给后端。

### 2.2 请求体结构（`http_assistant_api.dart`）

```json
{
  "message": "用户本次输入的文字",
  "agent_id": "agent_xxx",
  "history": [
    { "role": "user", "content": "..." },
    { "role": "assistant", "content": "..." }
  ],
  "agent_name": "智能体名称",
  "agent_role": "智能体职能内容（多行文本）"
}
```

- `message`：必填；也兼容后端读取 `userMessage`。
- `agent_id`：必传；后端当前仅做透传/日志，未参与 prompt 拼接。
- `history`：可选，数组；仅包含 `role` 与 `content`，按时间顺序（从旧到新）。
- `agent_name`、`agent_role`：可选；为空或不传时后端使用默认名称「智能助手」、空职能。

### 2.3 前端不做的加工

- 不拼 system prompt；
- 不截断 history（截断在后端）；
- 不注入任何额外 system/user/assistant 文案，只做字段透传。

## 三、后端：接收后的拼接与加工

### 3.1 解析请求体（`api_only_app.py` 中 `/api/chat`）

- `message` 或 `userMessage`：当前轮用户输入，经 `_normalize_message_content`（去首尾空白）。
- `agent_name`：默认 `"智能助手"`。
- `agent_role`：默认 `""`。
- `history`：必须是 list，否则按空列表处理。

### 3.2 加工一：System Prompt 的生成

函数：`_build_system_prompt(agent_name, agent_role)`。

- **有职能时**：
  ```text
  你是「{name}」。

  你的职能/角色：
  {role}

  请严格按上述身份与职能，用自然、友好的口吻直接回复用户，不要复述身份说明。
  ```
- **无职能时**：
  ```text
  你是「{name}」。请用自然、友好的口吻直接回复用户。
  ```

即：后端用「名称 + 职能」拼成**一条** system 文案，不再追加其他固定话术。

### 3.3 加工二：History 的规范化

函数：`_normalize_history(history)`。

- 遍历前端传来的 `history`，每条只取 `role` 与 `content`；
- `role` 只保留 `user` 或 `assistant`，其它一律视为 `user`；
- `content` 为空或仅空白则丢弃该条；
- **只保留最近 80 条**（按条数，约 40 轮对话，支持长对话记上下文），保证发给模型的上下文长度可控。

得到：`[ {"role":"user"|"assistant", "content":"..."}, ... ]`，顺序与前端一致（从旧到新）。

### 3.4 加工三：发给大模型的 messages 组装

```python
messages = [
    {"role": "system", "content": system_content},   # 上面拼好的 system prompt
    ...history,                                        # 规范化后的历史，最多 80 条
    {"role": "user", "content": message}              # 当前轮用户输入
]
```

- **仅在此处**出现 `system` 角色；
- 当前轮用户消息**只放一条**在最后，不重复出现在 history 里（前端传的 history 本身就不含本条）。

## 四、后端：调用大模型 API 与回传

### 4.1 请求大模型

- 接口：`POST {MODEL_BASE_URL}/chat/completions`（OpenAI 兼容，如豆包火山方舟）。
- Headers：`Authorization: Bearer {MODEL_API_KEY}`，`Content-Type: application/json`。
- Body：
  ```json
  {
    "model": "MODEL_ID",
    "messages": [ /* 上节中的 messages */ ],
    "stream": true
  }
  ```
- 后端以**流式**读取响应，但在当前实现中**只聚合完整回复文本**，不逐 chunk 推给前端。

### 4.2 流式响应的处理

- 解析 SSE 行，取 `data: {...}` 中 `choices[].delta.content`（或 `delta.text`）；
- 拼成 `full_reply`，直到遇到 `[DONE]` 或流结束；
- 异常或非 200 时，将上游错误信息放入异常并返回 500，前端会看到「请求失败: 500 - ...」。

### 4.3 返回给前端的 JSON

```json
{
  "reply": "模型生成的完整回复文本",
  "memory_connected": false,
  "memory_full": false
}
```

- `reply`：必读字段，前端直接作为当条 assistant 消息内容；
- `memory_connected` / `memory_full`：当前固定为 `false`，为后续扩展预留。

若请求失败，后端返回 HTTP 500，body 为 `{"error": "错误信息..."}`，前端会解析并展示为「请求失败：...」。

---

## 五、前端：收到回复后的处理

### 5.1 解析与展示（`http_assistant_api.dart` + `agent_chat_page.dart`）

- 只读 `response.body` 中 JSON 的 `reply` 字段（字符串）；
- 构造 `ChatMessage(role: 'assistant', content: reply)`；
- 调用 `repository.addMessage(agent.id, assistantMsg)` 写入本地；
- 刷新列表并滚动到底部，在气泡中显示 `message.content`。

### 5.2 错误处理

- 非 200 或无 `reply`：抛异常，前端 catch 后构造一条「请求失败：$e」的 assistant 消息并同样写入本地并展示，保证对话流不断裂。

## 六、数据流小结表

| 阶段 | 输入 | 加工 / 输出 |
|------|------|-------------|
| 前端组包 | 当前输入、历史列表、agent.name / agent.role / agent.id | 请求体：message, history, agent_name, agent_role, agent_id |
| 后端解析 | 请求体 | message, agent_name, agent_role, history（raw） |
| 后端拼 system | agent_name, agent_role | system_content（一段完整 system 文案） |
| 后端规范 history | history（raw） | 最多 80 条，仅 user/assistant，有内容的条 |
| 后端组 messages | system_content, history, message | [system, ...history, user] 发给模型 |
| 模型 API | messages | 流式返回 content → 后端聚合成 full_reply |
| 后端返回 | full_reply | JSON：reply, memory_connected, memory_full |
| 前端展示 | reply | 一条 assistant 消息写入本地并显示在气泡中 |

## 七、本地对话管理（复制 / 单删 / 多选批量删）

与常见 IM 类似：**长按气泡**弹出底部操作表：

| 操作 | 行为 |
|------|------|
| **复制文字** | `Clipboard.setData`，SnackBar 提示 |
| **多选** | 进入多选模式，当前长按的一条默认已选；点击其他条切换选中；顶栏显示「已选 n 条」+ **删除** |
| **删除本条** | 二次确认后按消息 **id** 从内存列表移除并写回 `messages_<agentId>.json` |

- **ChatMessage.id**：每条消息持久化唯一 id（`toJson`/`fromJson` 读写）；旧数据无 `id` 时 `fromJson` 会生成并下次保存时写回。
- **AssistantRepository**：`removeMessageById`、`removeMessagesByIds` 删完后统一 `_saveMessages`。
- 多选模式下底部输入栏隐藏，避免误触；点左上角关闭退出多选。
